# 一、 软件定位与核心设计哲学

针对硬件工程师在日常调试与打样验证中的实际诉求，LinkNexus 坚持以下核心设计原则：
1. **完全基于 Windows 设备管理器真实识别**：
   - 彻底删除一切“端口 #xxx”、“CH通道”、“通道 A/B”等人工编造的序号或前缀标签；
   - 设备卡片的主名称**完全以 Windows 操作系统识别出来的设备友好名称（FriendlyName / Name）为主名字**，不生造任何自定义名字；
   - **没识别到就不显示卡片**：只有在 Windows 中被真实枚举到的物理设备才在界面顶部呈现，拔出后卡片自动消失。
2. **选中设备即展开独立专属工作台**：
   - 识别到 FT2232、XDS110、DAP 等烧录器时，自动分配为独立烧录与内核调试工作台（支持 bin/hex 烧录、读取扇区 Hex 转储、整片擦除、CoreID 读取、软复位）；
   - 识别到 CH343P / USB 串口功能时，自动分配为独立串口工作台（支持波特率切换、字符串与十六进制 HEX 收发、Linux 卡片机 CLI 命令行终端交互）；
   - 插入 U 盘等其他下行设备时，以 Windows 识别的设备名展示硬件底层参数。
3. **ESP32-S3 后台隐藏，专属守护状态联动**：
   - ESP32-S3 核心主控不占用顶部卡片与独立页面，隐匿于后台执行管理总线；
   - 其状态直接驱动左下角的“LinkNexus 物理拓扑守护服务”，彻底去除任何暴露芯片型号的多余字样，严格纯粹只显示守护服务是否在线和对应颜色图标状态：
     * **🟢 绿色**：`LinkNexus 物理拓扑守护服务：在线` (服务正常运行中)；
     * **🔴 红色**：`LinkNexus 物理拓扑守护服务：离线` (服务脱机)；
     * **🟡 黄色**：`LinkNexus 物理拓扑守护服务：异常` (驱动失效或枚举异常)。
4. **Debug 维护模式唯一化**：
   - 仅限在右下角规范版本号区域 **1.5 秒内连续点击 5 次开启/关闭**，彻底去除标题栏或其他位置多余的调试按钮与快捷键。
5. **彻底去噪，删除冗余供电查看卡片**：
   - 删除了原有的“目标板下行供电输出 (VBUS)”与硬件互锁查看页面，将主界面 100% 的视觉焦点分配给当前所选设备的专属操作台。

# 三、 当前已落地功能实现逻辑详解 (自然语句解读)

### 1. 物理端口动态平铺与 Windows 真实主名称识别 (无多余标识)
- **自然语言描述**：
  软件界面顶部平铺端口卡片，严格按照 Windows 操作系统的枚举顺序动态排列：
  - **彻底删去“端口 #1”、“端口 #2”等区分顺序的生硬标识**；
  - **主名称直接使用 Windows 识别出来的设备名字**（如 `FT2232H Dual High Speed USB to Multipurpose UART/FIFO IC`、`CMSIS-DAP Debugger`、`USB-SERIAL CH343 (COM4)`、`SanDisk Ultra USB 3.0` 等），不使用任何自定义别名；
  - **没有识别到的设备直接不显示卡片**（卡片集合是完全动态增删的，插上即显，拔出即隐）；
  - **驱动就绪时自动从设备管理器抓取真实序列号**并高亮显示系统分配的真实 COM 端口号；若驱动未装好（Code 28）则标黄提示，拒绝伪造假数据。

---

### 2. 独立专属工作页面体系 (FT2232 / XDS110 / DAP / CH343P / U盘)
- **自然语言描述**：
  点击顶部任意设备卡片，下方主区域立即切换为该设备**专用的独立工作页面**：

#### 2.1 固件烧录与内核工作组件独立页面 (适用于 FT2232、XDS110 探针、DAP)
- **多通道复合设备智能解耦 (解决 XDS110 烧录与串口混淆 Bug)**：
  * 针对 TI XDS110 等官方复合烧录器，系统自动进行硬件能力侦测与双通道解耦：
    - 无 COM 口的 JTAG/SWD 硬件调试探针（`XDS110 Class Debug Probe`）精准挂载本烧录工作台（角标显示 `🛠️ TI XDS110 烧录探针`）；
    - 带有 COM 端口的通信通道（`XDS110 Class Application/User UART` / `Auxiliary Data Port`）精准分流至 2.2 节串口工作台（角标显示 `📡 XDS110 虚拟串口`），彻底消除两个通道混为一谈的错误。
- **全局工业暗黑滑动条体系 (解决多设备堆叠遮挡烧录进度与日志 Bug)**：
  * 在烧录工作台外层完整集成暗黑自适应 `ScrollViewer`，无论顶部平铺多少行设备卡片，页面均可丝滑向下滚动，确保烧录进度条、传输速率与下方的 Hex Dump / 内核日志视窗绝不被裁剪。
- **固件放入区**：支持拖拽或浏览 `.bin`、`.hex`、`.elf` 镜像，实时计算 CRC32、显示容量与匹配芯片架构，并提供可配置的烧录基地址（默认 `0x08000000`）。
- **内核操作组件**：
  * **`[▶ 开始执行固件烧录]`**：流式写入固件，动态显示进度条与 `218 KB/s` 写入速率，比对片上 CRC32，执行系统复位；
  * **`[📖 读取扇区数据 (Read Sector)]`**：从目标 MCU 基址读取 256 字节，并在左侧 **Hex Dump 视窗** 中以标准的 16 进制转储格式（地址 + 十六进制字节 + ASCII 字符）清晰呈现 Flash 扇区数据；
  * **`[🧹 整片快速擦除 (Chip Erase)]`**：执行整片 Flash 快速擦除并校验空片；
  * **`[⚡ 读取芯片 CoreID]`**：在线读取目标内核 CoreID 寄存器（如 Cortex-M4F `0x2BA01477`）并在顶部状态栏指示；
  * **`[🔄 硬件/系统复位 (SYSRESET)]`**：触发下位机复位引脚或软件内核复位。

#### 2.2 CH343P / XDS110 串口调试与 Linux CLI 独立页面 (适用于 CH343P / XDS110 虚拟串口 / 通用串口)
- **纯暗黑工业波特率选择器 (彻底消除全白 Bug)**：
  * 定制了深色 ComboBox 与 ComboBoxItem 模板，弹出的选择菜单背景为 `#18181B`、高亮态为 `#27272A` / `#38BDF8`，选中态为 `#0369A1`，字体为高对比亮白，彻底消除了系统默认全白弹窗刺眼的问题；
  * 提供完整的波特率阶梯：`9600`、`19200`、`38400`、`57600`、`115200`、`230400`、`460800`、`921600`、`1500000`、`2000000`、`3000000`，点击 `[打开串口 / 关闭串口]` 一键通断。
- **硬件流控引脚与下位机复位脉冲 (DTR / RTS / CTS / DSR)**：
  * **`[DTR 开关]`**：高低电平动态翻转，激活时亮绿；
  * **`[RTS 开关]`**：请求发送引脚动态控制，激活时亮绿；
  * **`[CTS 状态灯]`**：清晰指示硬件握手是否 Clear To Send；
  * **`[DSR (DTS) 状态灯]`**：实时监视下位机载波/就绪状态；
  * **`[⚡ DTR/RTS 脉冲复位]`**：专为 ESP32 / STM32 开发板设计的自动复位时序脉冲（拉低复位 -> 释放启动）。
- **全智能自适应输入与自动分类分流引擎**：
  * **自动识别（免去手动切模式易出错问题）**：输入框输入内容时，系统毫秒级动态分析指令特征并在右上角呈现动态彩色胶囊指示：
    - `[🐧 Linux CLI]`：识别到 `uname`、`ifconfig`、`dmesg`、`ls`、`cat`、`reboot` 等 shell 命令时，自动归类并直接下发至 Linux 终端流水；
    - `[🔢 HEX Frame]`：识别到成对十六进制序列（如 `AA BB 01 02`），直接以原始二进制字节帧下发；
    - `[📡 AT Command]`：识别到 `AT+...` 调制解调器指令；
    - `[📝 Plain Text]`：识别到普通文本字符串；
  * **快捷与按键交互**：支持敲击回车或点击 `▶ 执行 / 发送 (Enter)` 触发，并提供快捷命令一键注入条（`uname -a`、`ifconfig -a`、`dmesg | tail`、`top`、`reboot`、`clear`）。
- **三大布局自由切换**：
  * **🤖 智能双视窗**：左列 3* 宽度展示 Linux 卡片机 CLI 交互终端，右列 2* 宽度展示串口数据接收监视与 HEX 分析器，中间由 GridSplitter 分割可自由拖动；
  * **🐧 纯 CLI 终端**：全宽独占式 Linux Shell 命令行终端；
  * **📡 纯串口监视**：全宽独占式串口数据监视器（支持 HEX/字符串切换、时间戳与 TX/RX 字节统计）。

#### 2.3 通用 USB 外设与外部存储独立页面 (适用于 U盘 / 其它外设)
- 按照 Windows 识别出来的名字作为主标题，展示设备实例路径、硬件识别码、驱动服务名与连接健康状态。

### 6. 固件放入、位移查表 CRC32 与芯片架构识别
- 支持全窗口以及工作台 Dropzone 拖拽放入 `.bin`、`.hex`、`.elf` 镜像；
- 采用零依赖纯位移查表算法，数毫秒内计算真实 CRC32（如 `0x9B41E280`）；
- 智能识别 ARM Cortex-M4F (STM32F4xx)、Xtensa LX7 (ESP32-S3)、TI Stellaris (TM4C1294)、WCH RISC-V (CH32V305) 架构。

### 7. 工程规范版本号命名标准
