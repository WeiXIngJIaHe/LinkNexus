# 一、 软件定位与核心设计哲学

传统硬件调试器上位机常常面临以下三个典型痛点：
1. **命名混乱**：内部工程代号满天飞（如“CH通道”、“通道 A/B”），脱离了板卡外壳上印制的物理插口；
2. **数据造假/弱反馈**：界面展示假数据或粗暴的定时器轮询，无法真实反映 Windows 设备管理器中的驱动就绪情况（如驱动未安装 Code 28、硬件故障 Code 43 等）；
3. **缺乏供电保护**：目标板外部供电开关缺乏硬件互锁，由于手滑或主控未连通导致强行加电，引发浪涌反灌烧毁芯片。

**LinkNexus 的设计初衷**：
- **物理端口唯一化**：以硬件外壳真实的 `端口 #1` 至 `端口 #4` 作为唯一认知标准。
- **三态真实反映**：未插入就是灰色压暗，驱动坏了就是黄色告警，驱动就绪才是绿色，拒绝捏造假 COM 口。
- **硬件联动互锁保护**：只有主控 ESP32 在线且握手成功，才允许开启下行供电；主控掉线，上位机 1ms 内硬切断供电并自锁。
- **工业低噪美学**：彻底剔除口号式文本，深灰暗黑质感，界面核心全部留给硬件参数矩阵与控制开关。
- **隐藏式调试工作台**：日常干净整洁，需要测试、验证芯片架构或模拟烧录时，通过暗门或快捷键一键呼出强大的全功能预览调试台。

# 二、 总体系统分层架构设计

系统自底向上严格划分为 4 层架构，保证软硬件彻底解耦：

```
┌────────────────────────────────────────────────────────────────────────┐
│                        LinkNexus 四层分层软件架构                        │
└────────────────────────────────────────────────────────────────────────┘

 [4. 表现层: WPF 工业暗黑 UI]
  └─ WindowChrome 沉浸式标题栏 (去噪留白) + 端口卡片流 + VBUS 互锁仪表 + 双视窗工作台
                            ▲
                            │ 数据绑定 (DataBinding / Commands)
                            ▼
 [3. 业务层: MVVM 反应式调度中枢]
  ├─ MainViewModel: 状态机决策、CRC32 计算、芯片识别、烧录/负载模拟
  └─ PortDeviceModel: 单端口模型 (三态状态、MOS 通断控制、模拟插拔)
                            ▲
                            │ 异步事件驱动 / 回调通知
                            ▼
 [2. 系统底层通信层: Win32 PnP 驱动引擎]
  ├─ UsbMonitorService: 注册 RegisterDeviceNotification，截获 WM_DEVICECHANGE
  ├─ WMI 查询引擎: 250ms 消抖，扫描 Win32_PnPEntity 并解析 Code 28/10/43 错误码
  └─ Esp32CommService: 全双工 CDC 串口驱动，解析 0xAA 0x55 防粘包协议帧
                            ▲
                            │ 物理 USB / COM / 内部硬件母线
                            ▼
 [1. 物理硬件层: LinkNexus 多协议工作站]
  ├─ 拓扑中枢: CH338X 工业级 USB Hub
  ├─ 物理引擎 1: FT2232HQ 双通道 JTAG / 高速串口 (0403:6010)
  ├─ 物理引擎 2: DAPLink (CH32V305 RISC-V) 高速仿真器 (0D28:0204)
  ├─ 物理引擎 3: XDS110 (TM4C1294 Cortex-M4) TI 专用仿真器 (0451:BEF3)
  ├─ 物理引擎 4: ESP32-S3 全双工管理通信主控 (303A:1001)
  └─ 电气控制: INA236 母线电流电压采样芯片 + VBUS 供电 MOS 隔离管
```

# 三、 当前功能实现逻辑详解 (自然语句解读)

### 1. 物理端口排列与真实 USB 三态监测机制
- **自然语言描述**：
  软件界面顶部平铺 4 个端口卡片，严格对应板载的 4 个硬件调试引擎（端口 #1 至 端口 #4）。软件不使用定时间隔轮询，而是把窗口句柄挂载到 Windows 原生消息泵（`WndProc`），当用户插入或拔掉任意 USB 设备时，操作系统底层广播 `WM_DEVICECHANGE` 消息，上位机捕获后重置一个 250ms 的定时器进行消抖（防止 USB 复合设备连续产生十几个消息导致界面卡顿）。
- **三态判定规则**：
  1. **灰色压暗 (Unplugged)**：设备未插入物理插口，卡片上的 VID/PID、COM 口、序列号全部显示为 `--`。
  2. **黄色警告 (Warning)**：检测到了硬件插入（匹配到了目标 VID/PID 或未知设备），但设备管理器里显示黄色感叹号（驱动未安装 Code 28、设备无法启动 Code 10、硬件故障停止 Code 43）。此时卡片高亮淡黄色，右上角显示“⚠️ 驱动未就绪”，真实显示错误码，不编造虚假数据。
  3. **绿色就绪 (Ready)**：驱动安装完全正确，自动从 Windows 设备管理器抓取分配到的真实端口号（如 `COM3`）和硬件序列号，卡片点亮绿色就绪灯。

---

### 2. 目标板下行供电 (VBUS 5.0V) 硬件联动互锁机制
- **自然语言描述**：
  界面左下角设有对外输出供电的总开关。为了防止目标板被乱加电烧毁，软件设计了**强互锁逻辑**：
  - **互锁前提**：必须满足 `端口 #4 (ESP32-S3 主控)` 处于绿色 `Ready` 状态（代表主控在线并握手成功）。
  - **锁定保护**：若 ESP32-S3 未连接，整个下行供电控制区强制呈现半透明置灰（`Opacity=0.4`），鼠标悬停显示禁止操作手势，提示文字为橙色警告“🔒 硬件联锁已锁定：ESP32-S3 未连接，禁止操作输出”。
  - **意外断开即刻跳闸**：如果当前正在供电（5.0V 输出中），此时若 ESP32-S3 被拔出或掉线，上位机在捕获到掉线事件的瞬间（1ms 内），强制将供电状态重置为关断，电压电流读数归零，并在日志终端中高亮标红报警。

---

### 3. 开发者调试模式 (Debug Mode) 多维唤醒机制
- **自然语言描述**：
  LinkNexus 日常运行时呈现极简、无噪点的纯净工业监控形态。当需要进阶维护、测试电路或模拟故障时，可以通过 4 种途径激活“开发者调试模式”：
  1. **暗门 5 次连击**：1.5 秒内连续点击界面右下角的版本号 5 次（队列算法自动剔除超时点击）；
  2. **键盘快捷键**：按下键盘 <kbd>F12</kbd> 键，全局即刻切换；
  3. **标题栏按钮**：点击标题栏右上角的 `[DEBUG 模式]` 状态胶囊；
  4. **拖拽文件即入**：把任意固件或配置文件直接拖入软件窗口，自动唤醒调试模式并展开解析视窗。
- **唤醒后的界面响应**：
  - 标题栏中间显现琥珀色提示徽章；
  - 4 个端口卡片底部自动展开微型调试操作条；
  - 右侧控制台自动切换出文件放入区与全功能预览调试工作台。

---

### 4. 端口级物理通断 (MOS 隔离) 与状态机循环仿真
- **自然语言描述**：
  进入调试模式后，每个端口卡片底部出现两个按钮：
  - **`[端口开启 / 关断]`**：用于仿真硬件切断该端口的 MOS 管供电与信号。点击关断后，端口卡片立即置灰为离线状态，日志记录切断事件；再次点击则恢复导通。
  - **`[模拟插拔]`**：在没有真实硬件插拔的情况下，工程师可以单步循环改变该端口的状态：
    `离线未接入 (灰)` $\rightarrow$ `正常就绪 (绿)` $\rightarrow$ `驱动异常 (黄)` $\rightarrow$ `离线未接入`。
    特别地，若将 `端口 #4` 切换为离线或异常，可以立即观察到左侧的 VBUS 下行供电触发硬件自锁切断。

### 5. 固件/配置文件拖拽放入与芯片架构智能识别引擎
- **自然语言描述**：
  调试模式下展现出一个专属的“📂 放入文件”虚线框（同时支持全局全窗口拖放）。
  - **文件拖入**：支持 `.bin`、`.hex`、`.elf` 固件镜像与 `.json` 配置文件。
  - **秒级哈希校验 (CRC32)**：上位机内置纯位移查表算法，不依赖第三方库，数毫秒内算出 32 位校验和（如 `0x9B41E280`）并显示精确字节数。
  - **智能识别目标芯片架构**：根据文件头信息和命名模式，自动匹配芯片平台：
    * `ARM Cortex-M4F (STM32F4xx)`
    * `Espressif Xtensa LX7 (ESP32-S3)`
    * `TI Stellaris/Tiva (TM4C1294)`
    * `WCH QingKe RISC-V (CH32V305)`
    * `LinkNexus CH338X 拓扑配置文件`

### 6. 开发者全功能预览与调试工作台 (4 大工作台)
- **自然语言描述**：
  右侧控制台集成了 4 个可在上位机直接交互预览的工程调试选项卡：
  1. **固件烧录流水线预览 (TabFlash)**：
     - 点击“启动固件烧录流水线预览”，模拟真实的完整烧录生命周期：
       `SWD 10MHz 握手挂起内核` $\rightarrow$ `扇区擦除` $\rightarrow$ `流式分块高速写入 (实时显示 218 KB/s 与进度条)` $\rightarrow$ `片上 CRC32 比对校验` $\rightarrow$ `内核软复位运行`。
  2. **虚拟串口回环测试 (TabSerial)**：
     - 支持输入 `AT+SYSINFO?`、`AT+VERSION?`、`PING` 或任意文本。点击发送后，模拟下位机在 60ms 内回环响应，并在终端滚动输出，同时精确统计 TX/RX 累计收发字节数。
  3. **VBUS 动态负载阶跃仿真 (TabLoad)**：
     - 提供 `0 mA`、`150 mA`、`500 mA`、`1200 mA`、`2000 mA` 5 个阶跃按钮。模拟 $80\text{m}\Omega$ 电源回路等效内阻，点击后动态计算母线压降（例如 1200mA 下电压从 5.03V 跌至 4.93V），左侧电压表与电流表实时联动刷新。
  4. **ESP32 二进制协议帧校验 (TabProtocol)**：
     - 支持构造 `0x01 心跳包`、`0x10 遥测请求`、`0x30 供电控制` 协议帧，展示基于 `0xAA 0x55` 帧头的十六进制原始报文并实时比对 Checksum 累加和。

---

### 7. ESP32-S3 全双工二进制防粘包协议总线
- **自然语言描述**：
  上位机与 ESP32-S3 主控通过 CDC 虚拟串口建立全双工通信，协议格式规避了 ASCII 字符解析的高开销，采用紧凑的定长/变长二进制帧：
  - **帧结构**：
    `[0xAA][0x55] (2字节帧头) + [CMD] (1字节命令) + [LEN] (1字节载荷长) + [PAYLOAD] (N字节数据) + [CHECKSUM] (1字节校验和)`
  - **校验机制**：所有前序字节算术累加和模 256，接收端校验失败即刻丢弃并请求重发。

---

### 8. 硬件拓扑解耦与运行期配置热重载 (HardwareConfig.json)
- **自然语言描述**：
  硬件改版（打样新板、换引脚、换 Hub 端口）时，**绝不在 C# 代码中改死端口和 GPIO**。
  - 根目录提供了 `HardwareConfig.json` 描述每个逻辑端口绑定的芯片、Hub 物理端口、ESP32 供电引脚和 INA236 采样通道。
  - 在调试模式下触发“重载配置”，上位机即刻重新读取 JSON 并热更新映射，上位机**免编译、秒级适配新硬件**。

---

### 9. 工程规范版本号命名与暗门管理
- **自然语言描述**：
  版本号由算法自动动态生成，严格符合 `vXXxx.YYWW (XXX)` 标准规范：
  - 格式如：`v0100.2639 (PRE)`（主版本 01，次版本 00，2026 年第 39 周，预发布版）。
  - 版本号既是合规标尺，也是进入调试模式的“暗门”。

# 四、 界面与视觉工程规范 (UI Design System)

1. **工业暗黑配色**：
   - 主底色采用 `#18181B`（锌灰暗黑），卡片表面采用 `#121215`，边框采用 `#27272A`。
   - 绿色（`#10B981`）代表就绪与电流，青蓝（`#38BDF8`）代表电压与通信，黄色（`#F59E0B`）代表警告与调试，红色（`#EF4444`）代表故障与关断。
2. **标题栏彻底去噪**：
   - 顶部去除了原先陈旧的“硬件架构：4 路物理调试引擎 + 下行 VBUS 智能互锁输出”文字，保留左侧品牌标与纯净拖拽区。
   - 只有在开启 Debug 模式时，中央才浮现小巧的琥珀色工作状态指示。
3. **双视窗切换**：
   - 日常模式展示“PnP 硬件监控流”，等宽字体展示毫秒级驱动插拔日志；
   - 调试模式切换为“开发者功能预览工作台”，呈现 4 大选项卡式调试操作区。
