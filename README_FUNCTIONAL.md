### 1. 物理调试引擎矩阵与无歧义物理端口排列

系统彻底废除传统嵌入式调试站中混淆的内部工程代号（如“CH通道 / 通道 A / 通道 B”等），严格以**物理端口序号**（`端口 #1` 至 `端口 #4`）作为面向用户的唯一标识：

| 物理端口 | 物理调试/主控引擎 | 硬件核心芯片 | 硬件协议栈能力 | 默认目标 VID/PID |
| :--- | :--- | :--- | :--- | :--- |
| **端口 #1** | **FT2232HQ 双通道串口/JTAG 调试器** | FTDI FT2232HQ | 双通道 MPSSE 引擎、JTAG/SWD、高速虚拟串口 (最高 12Mbps) | `0403:6010` / `0403:6014` |
| **端口 #2** | **DAPLink (CH32V305) 仿真器** | WCH CH32V305 (RISC-V) | ARM CMSIS-DAP v2 高速硬件仿真链路、全速隔离调试串口 | `0D28:0204` / `1A86:7523` |
| **端口 #3** | **XDS110 (TM4C1294) 仿真器** | TI TM4C1294NCPDT | TI ARM Cortex-M 专用隔离烧录探针、CJTAG/SWD、EnergyTrace | `0451:BEF3` / `0451:BEF2` |
| **端口 #4** | **ESP32-S3 核心通信与控制主控** | Espressif ESP32-S3 | 全双工二进制管理总线、INA236 遥测采集、下行 VBUS 电源联锁中枢 | `303A:1001` / `303A:0002` |

### 2. 目标板下行供电 (VBUS 5.0V) 硬件联动互锁机制

为防止在无主控协调保护时盲目对外供电击穿目标板，软件实现了严格的**硬件级安全联锁校验**：

```
                      ┌──────────────────────────────┐
                      │    Windows 上位机 LinkNexus   │
                      └──────────────┬───────────────┘
                                     │
                             (USB PnP / COM 握手)
                                     ▼
                      ┌──────────────────────────────┐
                      │    端口 #4: ESP32-S3 主控    │
                      └──────────────┬───────────────┘
                                     │
           ┌─────────────────────────┴─────────────────────────┐
           │                                                   │
  [主控在线且握手成功]                                [主控离线 / 异常拔出]
           ▼                                                   ▼
┌─────────────────────────────┐                     ┌─────────────────────────────┐
│ 🔓 VBUS 控制区解锁 (Enabled) │                     │ 🔒 VBUS 控制区强制锁定置灰  │
│ 允许用户导通 5.0V MOS 输出   │                     │ 即刻硬切断供电输出 (0V/0mA) │
└─────────────────────────────┘                     └─────────────────────────────┘
```

- **互锁逻辑**：
  - 上位机界面仅在 `Ports[3].State == DeviceState.Ready`（ESP32-S3 在线且枚举正常）时，下行动力供电开关（`IsVbusPowerEnabled`）才处于可用状态（`IsEnabled = True`）。
  - 若主控尚未接入或发生意外拔出，VBUS 控件强制置灰锁定，杜绝任何误触操作。
  - **掉线保护切断机制**：上位机运行期一旦捕获到 ESP32-S3 断开事件（`WM_DEVICECHANGE` 广播），即便当前供电为导通状态，安全联锁逻辑将在 **1ms 内将供电指令复位为关断**，将母线电压与电流归零，并向事件流终端派发警告日志。

### 3. 开发者调试模式 (Debug Mode) 唤醒与运行机制

为了维持日常硬件调试时的纯净工业视野，所有工程维护、物理通断仿真、固件逆向解析等高级操作被深度集成在“开发者调试模式（Debug Mode）”中。支持 4 大维度无缝切入：

1. **暗门 5 次连击触发**：在主界面右下角工程版本号区域，1.5 秒内连续点击 5 次，平滑呼出调试模式。
2. **全局快捷键**：按下 <kbd>F12</kbd> 键，即刻完成调试模式的进入与退出切换。
3. **标题栏调试状态徽章**：点击标题栏右上角的 `[DEBUG 模式]` 状态胶囊，直观切换开关。
4. **外部文件拖拽直达**：从操作系统任意窗口拖拽 `.bin`、`.hex`、`.elf` 或 `.json` 文件进入窗口，系统自动唤醒调试模式并展开解析控制台。

### 4. 端口级物理通断 (MOS 隔离) 与状态机循环仿真

在开发者调试模式激活后，4 个物理端口卡片底部自动展开专属调试操作条，允许测试工程师在上位机界面直接验证拓扑容错逻辑：

- **物理通断开关 (`TogglePortEnableCommand`)**：
  - 点击 `[端口已开启] / [端口已关断]` 按钮，模拟硬件级切断该通道下行 MOS 管供电与 D+/D- 信号隔离。
  - 关断后卡片立即进入灰色离线待机状态，并在事件日志中记录硬件断开事件。
- **三态循环插拔模拟 (`ToggleSimulateStateCommand`)**：
  - 允许在无真实外设插拔的情况下，单步循环切换设备的三态：
    `Unplugged (离线未接入)` $\rightarrow$ `Ready (正常就绪)` $\rightarrow$ `Warning (驱动未就绪/硬件故障)` $\rightarrow$ `Unplugged`。
  - 用于验证各端口在驱动丢失（Code 28）、设备异常停止（Code 10/43）时的界面报警与降级处理。
- **联锁传导仿真**：将 `端口 #4` 切换为关断或异常状态时，可实时观察左侧下行 VBUS 供电联锁如何触发瞬间自锁保护。

### 5. 固件/配置文件拖拽放入与芯片架构智能识别引擎

调试模式提供专用的交互式文件放入区域（支持全窗口全局拖放与放入区高亮拖放）：

1. **文件基础元数据提取**：
   - 极速解析文件名、绝对路径、文件精准字节数（自动转换为 KB/MB 双尺度显示）。
2. **零依赖高速位移查表 CRC32 计算**：
   - 内置纯位运算与反向多项式（`0xEDB88320`）预计算查表算法，即使对于数兆字节的固件镜像，可在 10ms 级别内完成整包校验和计算，并格式化输出大写十六进制散列（如 `0x9B41E280`）。
3. **目标芯片架构与协议特征智能识别引擎**：
   - 自动剖析文件扩展名与命名特征，匹配底层编译工具链与芯片家族：
     * **ARM Cortex-M4F**：匹配 STM32F4xx / NXP LPC 等标准 32 位嵌入式微控制器固件。
     * **Espressif Xtensa LX7**：匹配 ESP32-S3 核心通信与控制主控固件。
     * **TI Stellaris/Tiva**：匹配 TM4C1294 隔离仿真器固件镜像。
     * **WCH QingKe RISC-V**：匹配 CH32V305 DAPLink 固件镜像。
     * **LinkNexus 拓扑配置**：匹配 CH338X 端口重映射 `HardwareConfig.json`。

### 6. 开发者全功能预览与调试工作台 (4 大工作台)

在界面右侧诊断区无缝集成了全功能预览与调试工作台，包含 4 大独立功能调试选项卡：

#### 6.1 固件烧录流水线预览 (Firmware Flash Pipeline)
- **仿真执行链路**：
  1. `步骤 1/4 (SWD 10MHz 握手)`：握手建立并挂起目标内核 (Halt & Unlock DAP)，读取目标 CoreID (`0x2BA01477`)；
  2. `步骤 2/4 (扇区快速擦除)`：执行 Sector Erase 基址 (`0x08000000 - 0x08040000`)；
  3. `步骤 3/4 (流式高速写入)`：分块流式写入固件镜像，动态计算传输速率（如 `218.4 KB/s`）与平滑进度条；
  4. `步骤 4/4 (片上 CRC32 严格比对)`：读取硬件寄存器比对本地镜像哈希，触发内核软复位 (`SYSRESETREQ`)。

#### 6.2 虚拟串口回环测试 (VCP Loopback Testing)
- 提供发送缓冲输入框，预设常用 AT 指令（`AT+SYSINFO?`、`AT+VERSION?`、`PING`）；
- 仿真自发自收回环响应机制，精确记录并显示累计 `Tx` 发送字节数与 `Rx` 接收字节数；
- 监视终端滚动输出带毫秒级时间戳的收发报文。

#### 6.3 VBUS 动态负载阶跃仿真 (Dynamic Load Step Simulation)
- 提供 `0 mA (待机)`、`150 mA (轻载)`、`500 mA (标称)`、`1200 mA (重载)`、`2000 mA (过流阈值)` 5 级动态阶跃控制；
- **真实内阻压降数学模型**：
  $$V_{bus} = 5.03\text{ V} - \left(\frac{I_{load}}{1000}\right) \times 0.08\,\Omega$$
  模拟板载导线与 MOS 等效内阻的毫伏级跌落（例如 1200mA 下电压跌落至 4.93V），左侧电压表与电流表毫秒级响应刷新。

#### 6.4 ESP32 二进制协议帧校验 (Binary Protocol Frame Inspector)
- 现场构造并验证基于 `0xAA 0x55` 引导头的定长/变长二进制协议报文；
- 预置心跳包（`0x01`）、INA236 遥测请求（`0x10`）、通道 MOS 供电控制（`0x30`）等命令字构造，并实时计算输出校验和（Checksum）及模拟下位机 ACK 字节。

### 7. 规范工程版本号体系与暗门交互规范

系统强制采用严格的工程规范版本号定义，杜绝随意定义的散乱版本：

$$\mathbf{v[XX][xx].[YY][WW]\ (XXX)}$$

- **XX**：大版本号（两位十进制，如 `01` 代表架构主版本 1）；
- **xx**：小版本或重大迭代编号（两位十进制，如 `00` 代表初始发布）；
- **YY**：年份后两位（如 `26` 代表 2026 年）；
- **WW**：ISO 8601 标准计算的自然周数（01 ~ 53，如 `39` 代表第 39 周）；
- **XXX**：三位大写发布阶段阶段标志：
  * `PRE`：预发布/内部工程验证版 (Pre-release)；
  * `REL`：正式量产发布版 (Release)；
  * `RC_`：候选发布版 (Release Candidate)。
- **示例输出**：`v0100.2639 (PRE)`。

### 4. VBUS 硬件联锁供电控制区外观与状态反馈

### 5. 交互式固件拖拽区 (Dropzone) 视觉与参数展布

- 采用青蓝浅框（`#38BDF8`），圆角 `6px`，支持全局拖放与特定区域放置；
- 拖入文件后以水平单行致密布局回显：
  `[📂 放入文件: firmware_v1.bin]  |  文件大小: 256.00 KB (262,144 字节)  |  CRC32: 0x9B41E280  |  匹配架构: ARM Cortex-M4F`。

---

### 6. 双视窗诊断控制台 (PnP 事件流 vs. 功能预览工作台)

右侧控制台支持单选切换两种截然不同的视图：
1. **PnP 硬件监控流（日常状态）**：包含时间戳、级别胶囊（`INFO` 灰、`WARN` 琥珀、`SUCCESS` 翠绿、`ERROR` 绯红）与等宽控制台字体，记录总线设备枚举全量过程。
2. **开发者功能预览调试（Debug 状态）**：自动切换为主工作台，包含 4 组 RadioButton 切换选项卡与互动操作控件。

# 三、 监听转发与通信协议规范 (Monitoring, Forwarding & Protocols)

### 1. Win32 原生 PnP 消息泵监听 (WndProc)

上位机绝不使用低效轮询，而是通过 WPF `HwndSource` 挂接 Win32 原生消息泵，注册设备通知句柄：

```csharp
// 注册监听 USB 设备与虚拟通信端口设备广播通知
DEV_BROADCAST_DEVICEINTERFACE filter = new()
{
    dbcc_size = Marshal.SizeOf(typeof(DEV_BROADCAST_DEVICEINTERFACE)),
    dbcc_devicetype = DBT_DEVTYP_DEVICEINTERFACE,
    dbcc_classguid = GUID_DEVINTERFACE_USB_DEVICE // 监听 USB 设备拓扑
};
RegisterDeviceNotification(hWnd, ref filter, DEVICE_NOTIFY_WINDOW_HANDLE);
```

- **截获的关键 Windows 消息**：
  - `WM_DEVICECHANGE (0x0219)`
  - `wParam = DBT_DEVICEARRIVAL (0x8000)`：检测到硬件物理接入事件；
  - `wParam = DBT_DEVICEREMOVECOMPLETE (0x8004)`：检测到硬件物理断开事件。

---

### 2. 异步消抖与 WMI 全量拓扑枚举机制

Windows 在设备插入时会接连触发多个接口子节点的 PnP 广播，导致短时间内并发风暴。系统设计了 **250ms 动态消抖时间窗**：

```
[USB 设备物理插入]
       │
       ├─► WM_DEVICECHANGE (Interface 0) ──┐
       ├─► WM_DEVICECHANGE (Interface 1) ──┼──► [250ms 计时器重置消抖] ──► 触发 WMI 拓扑枚举
       └─► WM_DEVICECHANGE (COM Port)    ──┘
```

- **WMI 查询语句**：
  `SELECT DeviceID, Name, PNPDeviceID, ConfigManagerErrorCode, Status FROM Win32_PnPEntity WHERE DeviceID LIKE 'USB%'`
- **真实硬件状态映射规则**：
  * 若 `ConfigManagerErrorCode == 0`：判定为驱动就绪（`Ready`），提取 COM 口号与序列号；
  * 若 `ConfigManagerErrorCode` 为 `28`（驱动未安装）、`10`（无法启动）、`43`（硬件故障停止）：判定为异常告警（`Warning`），提取真实 VID/PID 并上报异常代码，**拒绝捏造虚假 COM 口号**；
  * 若设备在当前枚举列表中不存在：复位为未连接（`Unplugged`）。

---

### 3. 虚拟通信串口 (VCP) 动态拓扑关联与转发

系统通过解析设备管理器中的友好名称（`FriendlyName`）与硬件路径中的符号链接提取虚拟串口号：
- 正则匹配表达式：`\((COM\d+)\)`
- 成功捕获后，将 `COMx` 动态挂载到对应的物理端口卡片视图，并作为后续串口回环测试与 AT 指令收发的目标通信信道。

---

### 4. ESP32-S3 全双工二进制防粘包协议总线

上位机与 ESP32-S3 核心管理主控之间通过 USB CDC 高速虚拟串口建立点对点二进制防粘包通信链路：

#### 4.1 协议帧通用格式 (Big-Endian)

| 字节偏移 | 字段名 | 长度 (Bytes) | 取值定义 / 说明 |
| :---: | :---: | :---: | :--- |
| `0` | **Header 0** | 1 | 固定同步引导头：`0xAA` |
| `1` | **Header 1** | 1 | 固定同步引导头：`0x55` |
| `2` | **Cmd** | 1 | 命令字（详见下表） |
| `3` | **Length** | 1 | 载荷长度 $L$ ($0 \le L \le 64$) |
| `4 ~ 4+L-1` | **Payload** | $L$ | 命令参数数据载荷 |
| `4+L` | **Checksum** | 1 | 累加和校验：$\sum (\text{Header} + \text{Cmd} + \text{Len} + \text{Payload}) \pmod{256}$ |

#### 4.2 核心命令字与定义表

| 命令字 (CMD) | 传输方向 | 名称 | 载荷描述 (Payload) |
| :---: | :---: | :--- | :--- |
| `0x01` | 上位机 $\leftrightarrow$ ESP32 | **心跳维持包** | `[0x01]` 维持通信租约与联锁状态 |
| `0x10` | 上位机 $\rightarrow$ ESP32 | **INA236 遥测采集请求** | `[0x00]` 请求实时采样母线电压与电流 |
| `0x11` | ESP32 $\rightarrow$ 上位机 | **INA236 遥测采集回执** | `[V_Hi, V_Lo, I_Hi, I_Lo]` (高位优先定点数) |
| `0x30` | 上位机 $\rightarrow$ ESP32 | **VBUS 供电开关指令** | `[0x01: 导通, 0x00: 关断, Check]` |
| `0x31` | ESP32 $\rightarrow$ 上位机 | **供电状态确认 ACK** | `[0x00: 成功, 0x01: 硬件故障, 0x02: 过流保护触发]` |
| `0x80` | 上位机 $\rightarrow$ ESP32 | **通道 MOS 物理隔离** | `[PortIndex (1~4), State (0/1)]` |

---

### 5. 硬件拓扑解耦与运行期配置热重载 (HardwareConfig.json)

为杜绝上位机源码中写死引脚号导致的硬件改版硬伤，所有通道与 Hub 物理端口、ESP32 GPIO 的绑定关系全部交由外部配置文件驱动：

```json
{
  "Version": "1.0.0",
  "HubChip": "CH338X",
  "PortMappings": [
    {
      "PortIndex": 1,
      "LogicalName": "端口 #1",
      "ChipTarget": "FT2232HQ",
      "PowerEnableGpio": 12,
      "Ina236Channel": 1
    },
    {
      "PortIndex": 4,
      "LogicalName": "端口 #4",
      "ChipTarget": "ESP32-S3",
      "PowerEnableGpio": 15,
      "Ina236Channel": 4
    }
  ]
}
```

- **热重载支持**：上位机运行期修改 `HardwareConfig.json` 后，在开发者调试模式下执行 `ReloadConfigCommand`，上位机无需重新编译，即可秒级完成端口与逻辑卡片的引脚重映射。
